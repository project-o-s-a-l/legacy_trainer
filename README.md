# Legacy Trainer

Legacy Trainer — учебная веб-платформа для практики рефакторинга legacy-кода.

Пользователь получает задачу с запутанным, частично некорректным кодом, находит баги, исправляет архитектуру и отправляет решение на автоматическую проверку. Основной сценарий проекта — переход от процедурного и плохо поддерживаемого кода к более чистой, понятной и расширяемой реализации. На первом этапе платформа ориентирована на Python-задачи.

## Что решает проект

Проект предназначен для тренировки практических навыков, которые редко отрабатываются на классических алгоритмических платформах:

- анализ legacy-кода;
- исправление логических и структурных ошибок;
- рефакторинг процедурного кода в сторону ООП;
- прохождение автоматических проверок;
- получение AI-обратной связи по качеству решения.

## Основные возможности

- каталог задач по рефакторингу и исправлению legacy-кода;
- поддержка языков программирования для задач и отправок решений;
- отправка пользовательского решения на проверку;
- запуск нескольких типов проверок:
  - тесты;
  - линтер;
  - статический анализ;
  - архитектурная проверка;
- подсчёт баллов за решение;
- сохранение истории отправок;
- AI-ревью решения с кратким summary, сильными сторонами, слабыми местами и рекомендациями;
- хранение прогресса пользователя по каждой задаче;
- теги и фильтрация задач.

## Целевая аудитория

- junior и middle Python-разработчики;
- студенты, изучающие рефакторинг и проектирование;
- преподаватели и менторы, которым нужен практический тренажёр;
- разработчики, готовящиеся к реальной работе с legacy-проектами.

## Пользовательский сценарий

1. Пользователь регистрируется и выбирает задачу.
2. Получает описание задачи и исходный legacy-код.
3. Исправляет баги и улучшает структуру решения.
4. Отправляет код на проверку.
5. Платформа запускает набор проверок и рассчитывает score.
6. При необходимости формируется AI-ревью решения.
7. Прогресс пользователя обновляется в профиле задачи.

## Архитектурная идея

Проект разделён на несколько логических зон:

- **backend** — API, бизнес-логика, работа с БД, проверка решений, AI-интеграции;
- **frontend** — интерфейс пользователя для просмотра задач, отправки решений и просмотра результатов;
- **database** — хранение пользователей, задач, отправок, проверок и прогресса;
- **infrastructure** — контейнеризация и локальный запуск окружения.

## Пример функциональных модулей backend

- **auth** — регистрация, логин, роли пользователей;
- **tasks** — список задач, просмотр задачи, фильтрация по тегам и сложности;
- **submissions** — отправка решений, получение истории отправок;
- **checks** — запуск и хранение результатов автоматических проверок;
- **ai_review** — генерация AI-оценки и рекомендаций;
- **progress** — прогресс пользователя по задачам;
- **users** — профиль пользователя и суммарная статистика.

## Пример API

Конкретный набор endpoint-ов может меняться по мере развития проекта.

## Локальный запуск

### Требования

- Docker
- Docker Compose

### Запуск через Docker Compose

```bash
git clone <repo_url>
cd legacy-trainer
cp .env.example .env
docker compose up --build
```

После запуска сервисы обычно доступны по следующим адресам:

- backend API: `http://localhost:8000`
- frontend: `http://localhost:3000`

Если используется стандартная конфигурация FastAPI, документация API будет доступна по адресам:

- `http://localhost:8000/docs`
- `http://localhost:8000/redoc`
